**2. What is IL and what is JIT?**

* **IL (Intermediate Language / CIL):** CPU-independent, intermediate bytecode generated by the C# or VB.NET compiler (`csc`). It allows source code written in different languages to share the same target representation before execution.
* **JIT (Just-In-Time Compiler):** A component of the CLR that compiles IL into machine-specific native code right at runtime when a method is first called. JIT operates in flavors like Normal JIT, Econo-JIT, and Tiered Compilation (Tier 0 for quick startup, Tier 1 optimized for hot paths).

```
C# Source Code ---> [Roslyn Compiler] ---> Assembly (.dll/.exe containing IL + Metadata)
Assembly        ---> [CLR / JIT Compiler] ---> Native Machine Code (0101...)

```

---

**3. What is CLR?**

The **Common Language Runtime (CLR)** (or CoreCLR in modern .NET) is the execution engine that manages .NET applications. Key responsibilities:

* Memory management via the Garbage Collector (GC)
* Code execution and JIT compilation
* Thread management and process isolation
* Exception handling
* Type safety and security enforcement

---

**4. What is CTS?**

The **Common Type System (CTS)** is the specification inside the CLR that defines how types (value types, reference types, classes, interfaces) are declared, used, and managed. It ensures type compatibility across different .NET languages:

* A C# `int` and a VB.NET `Integer` both compile to the CTS type `System.Int32`.

---

**5. What is CLS?**

The **Common Language Specification (CLS)** is a subset of rules defined under the CTS. To guarantee that a library written in one language (e.g., C#) can be consumed seamlessly by another (e.g., F# or VB.NET), code exposed publicly must comply with CLS rules.

* *Example rule:* Case-sensitivity is not CLS-compliant because languages like VB.NET are case-insensitive. Having public members named `GetValue()` and `getvalue()` in the same class breaks CLS compliance.

**6. What is MVC?**

MVC is an architectural design pattern that enforces the Separation of Concerns (SoC) principle by dividing an application into three distinct components:

* **Model:** Handles data schema, business logic, and state.
* **View:** Manages presentation, rendering data to the user interface.
* **Controller:** Intercepts user requests, processes them using business logic/services, updates models, and selects the corresponding view or JSON payload to return.

---

**7. Difference between Design Pattern and Architectural Pattern**

* **Architectural Pattern:** Governs the high-level structure, subsystem boundaries, and macro-architecture of the entire application. Examples: MVC, Microservices, Hexagonal/Clean Architecture, CQRS.
* **Design Pattern:** Governs low-level class and component interactions to solve concrete, recurring code problems within a specific subsystem. Examples: Factory, Singleton, Strategy, Observer, Repository.

---

**8. Advantages of ASP.NET MVC**

* **Separation of Concerns (SoC):** Distinct separation of UI, business logic, and routing makes applications maintainable and scalable.
* **Full Control over HTML/CSS/JS:** No hidden abstractions, ViewState, or synthetic events.
* **High Testability:** Controllers interact with abstractions, enabling straightforward unit testing and mocking.
* **Powerful Routing Engine:** Supports RESTful, SEO-friendly URI structures.
* **Rich Extensibility:** Custom filters, model binders, and action results allow easy pipeline modification.

---

**9. What is Model and View?**

* **Model:** The domain/business representation containing data and rules. In typical enterprise design, we separate this into Domain Models (entities mapped to databases) and ViewModels/DTOs (tailored specifically for UI or API exposure).
* **View:** A template file (`.cshtml`) containing HTML and lightweight server-side markup (Razor) responsible strictly for rendering presentation logic. It should not contain data access or business rules.

---

**10. What are the different types of Views?**

* **Standard View:** A complete view page bound to a controller action that renders within a shared layout (`_Layout.cshtml`).
* **Partial View:** A reusable view fragment rendered inside other views (equivalent to a reusable UI widget).
* **Layout View (`_Layout.cshtml`):** The master template defining common scaffolding (headers, footers, meta tags, shared script includes).
* **ViewStart (`_ViewStart.cshtml`):** Executes before any individual view executes; typically used to assign the default layout globally.
* **ViewImports (`_ViewImports.cshtml`):** Provides global namespaces, tag helpers, and dependency injection directives to all views.

---

**11. Different types / usages of Partial Views**

* **Static Reusable Snippets:** Shared navigation bars, headers, footers, or copyright banners.
* **Dynamic Item Templates:** Rendering individual rows or cards dynamically within a loop (e.g., a reusable `_ProductCard.cshtml`).
* **AJAX Content Payloads:** Rendered server-side and returned via AJAX requests to update a specific DOM section without a full page reload.

*Rendering in Modern ASP.NET Core:*

```csharp
// Tag Helper syntax (preferred)
<partial name="_ProductCard" model="item" />

// HTML Helper syntax (older)
@await Html.PartialAsync("_ProductCard", item)

```

---

**12. What is a View Engine?**

A View Engine parses view templates written with specific syntax, executes embedded server-side code, injects model data, and compiles the result into standard HTML sent to the client browser. In older ASP.NET versions, developers used the ASPX (Web Forms) view engine alongside Razor. In modern .NET, the **Razor View Engine** is the standard.

---

**13. What is Razor?**

Razor is a lightweight, clean templating markup syntax used to embed C# code directly into HTML markup using the `@` symbol. It does not require explicit closing tags like `<% %>` from classic ASPX, parsing context automatically:

```html
@if (Model.IsActive)
{
    <span class="badge bg-success">Active: @Model.Username</span>
}

```

**15. Explain MVC Architecture**

```
Browser (HTTP Request)
        |
        v
  [Routing Engine]
        |
        v
  [Controller] <---> [Business Services / Database / Model]
        |
        v
  (Passes Model)
        |
        v
    [View] ---------> (HTML Response) ---------> Browser

```

1. **Client sends request:** A URL request arrives at the application.
2. **Routing Engine:** The pipeline maps the route template (`{controller}/{action}/{id}`) to a specific Controller method.
3. **Controller handles request:** The action method executes, querying services or the database to fetch or mutate data.
4. **View population:** The controller constructs a ViewModel and passes it to the View.
5. **HTML Generation:** The View Engine compiles the View + Model into raw HTML and streams it back to the client.

**16. What is Dependency Injection (DI)?**

Dependency Injection is a design technique implementing the **Inversion of Control (IoC)** principle. Instead of an object instantiating its own dependencies directly (e.g., using `new Service()`), those dependencies are supplied ("injected") from the outside by an IoC container.

*Without DI (Tight Coupling):*

```csharp
public class OrderController : Controller
{
    private OrderService _service = new OrderService(); // Hard dependency
}

```

*With DI (Loose Coupling):*

```csharp
public class OrderController : Controller
{
    private readonly IOrderService _service;
    public OrderController(IOrderService service) => _service = service;
}

```

---

**17. Benefits of Dependency Injection**

* **Decoupled Architecture:** Classes depend on interfaces rather than concrete implementations.
* **Testability:** Dependencies can be swapped with mocks or stubs (e.g., Moq, NSubstitute) during unit testing.
* **Maintainability & Flexibility:** Swapping implementations (e.g., switching from `SqlOrderRepository` to `MongoOrderRepository`) requires updating only the composition root.
* **Centralized Lifecycle Management:** The IoC container controls creation, disposal, and resource scoping (Transient, Scoped, Singleton).

---

**18. How do we implement Dependency Injection?**

The three standard types of Dependency Injection:

* **Constructor Injection (Standard pattern):**

```csharp
public class PaymentProcessor
{
    private readonly ILogger<PaymentProcessor> _logger;
    public PaymentProcessor(ILogger<PaymentProcessor> logger) => _logger = logger;
}

```

* **Method Injection:** Used when a dependency is only needed by a single method rather than the whole class (e.g., using `[FromServices]` in ASP.NET Core):

```csharp
[HttpPost]
public IActionResult Checkout([FromServices] IPaymentGateway gateway, OrderDto order)
{
    gateway.Charge(order);
    return Ok();
}

```

* **Property Injection:** Setting dependencies through public properties. Less preferred because it risks temporal coupling (running code before the property has been set).

**19. Middleware in MVC / ASP.NET Core**

Middleware is software assembled into the application pipeline to handle requests and responses. Each component:

1. Receives an `HttpContext`.
2. Executes logic before passing the request to the next component.
3. Invokes the next middleware via `next.Invoke()`.
4. Executes logic on the response path as it returns up the chain.

Typical uses: Authentication, Authorization, Logging, CORS, Exception Handling, Static Files.

---

**20. How do we add Middleware?**

Middleware is registered in the application pipeline (in `Program.cs` or `Startup.cs`) using `IApplicationBuilder`:

* **Inline / Custom Lambda Middleware:**

```csharp
app.Use(async (context, next) =>
{
    // Logic before next component
    await next.Invoke();
    // Logic after next component
});

```

* **Dedicated Middleware Class:**

```csharp
public class RequestLoggingMiddleware
{
    private readonly RequestDelegate _next;
    public RequestLoggingMiddleware(RequestDelegate next) => _next = next;

    public async Task InvokeAsync(HttpContext context)
    {
        Console.WriteLine($"Request: {context.Request.Path}");
        await _next(context);
    }
}

// Registration via extension method
app.UseMiddleware<RequestLoggingMiddleware>();

```

**21. Use of Startup.cs file**

In classic ASP.NET Core (1.0 through 5.0, and optional in 6+), `Startup.cs` serves as the composition root:

* **`ConfigureServices(IServiceCollection services)`:** Registers services into the built-in IoC container and configures DI lifetimes.
* **`Configure(IApplicationBuilder app, IWebHostEnvironment env)`:** Configures the HTTP request processing pipeline by declaring middleware execution order.

*(Note: In .NET 6/7/8+, this was streamlined into a single `Program.cs` file using Top-Level Statements and `WebApplicationBuilder`.)*

**22. What is a ViewModel?**

A ViewModel is a model class designed specifically for a particular View. It differs from domain entities in that:

* It shapes data exactly to the UI's needs (e.g., combining data from multiple database entities into one view object).
* It contains UI-specific validation attributes (`[Required]`, `[EmailAddress]`, `[Compare]`).
* It prevents Over-Posting/Mass-Assignment vulnerabilities by ensuring the client cannot bind values to internal domain properties.

---

**23. What are Cookies?**

Cookies are small key-value text pairs sent by the server to the client browser via the `Set-Cookie` HTTP header.

* The browser stores them locally and attaches them automatically in the `Cookie` header for subsequent requests matching the same domain and path.
* **Security best practices:** Mark sensitive cookies with `HttpOnly` (mitigating XSS theft), `Secure` (ensuring transmission only over HTTPS), and `SameSite=Strict/Lax` (mitigating CSRF attacks).

---

**24. What is Session Management?**

HTTP is stateless; every request is independent. Session management represents techniques used to preserve state and user identity across multiple sequential requests:

* **In-Memory / Server-Side Session:** A unique `SessionID` is stored in a cookie on the client, while actual session data resides in server memory (or a distributed cache like Redis or SQL Server in load-balanced setups).
* **Token-Based / Stateless Management (JWT):** The client stores a signed cryptographic payload containing identity and claims, sending it inside the `Authorization: Bearer` header on each request.
* **Client-Side Storage:** Cookies, `localStorage`, or `sessionStorage`.

**25. What is .NET Framework?**

The **.NET Framework** is Microsoft's original, comprehensive software development platform launched in 2002 for building and running Windows-based applications. It consists of two primary pillars:

* **Common Language Runtime (CLR):** The managed execution environment providing memory management, security, JIT compilation, and OS interop.
* **Framework Class Library (FCL):** An extensive set of shared, reusable libraries providing standard APIs for file I/O, networking, database connectivity (ADO.NET), and application frameworks (ASP.NET Web Forms/MVC, WCF, WPF, and Windows Forms).
